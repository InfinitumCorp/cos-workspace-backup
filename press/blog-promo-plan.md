## 3. Method
1. One featured post per day (plus roundups). Release = news hook (new paper / new analysis / new series) + focus keyword + 3 factual takeaways taken only from the post + one quote taken verbatim from the post + the post's bare URL + homepage bare URL + boilerplate + contact.
2. Hook wording: "publishes", "releases", "outlines" - never "breaking", never hype adjectives.
3. Headline 55-80 chars; keyword + "Infinitum Corporation"; keyword in first sentence; brand within first 100 words; 300-500 words; summary 140-155 chars.
4. Links: max 2-3, all bare URL or brand anchor. Post URL first, homepage second. Do not link raw.githubusercontent.com PDF files from wires (link the blog page; it carries the PDF link). No Telegram/X/Discord links in blog releases.
5. Boost the blog directly: each live release gives the blog post URL a dated third-party mention (brand/entity signal). Expect nofollow-like treatment; do not rely on ranking.
6. Per-site variant: same post may only appear once per site. Variant = different headline, lede paragraph, angle (see table), quote, ordering of takeaways, and at least 80% new sentences vs. any earlier release (compare against daily-log.md). Different sites on different days; never the same text on two sites.
7. Duplicate-content guard: if a day's text shares >20% sentences with a prior release, rewrite.
8. Rotate through the 5-6 allowed posts twice (pass 1 Oct 27-Nov 2, pass 2 Nov 3-9) with a different angle each pass. Before writing, re-fetch both feeds; if Blog Bot has published a newer ALLOWED-tier post (business/security/AI/whitepaper topic), swap it into the next free day and push the pass-2 repeat later.
9. Measurement: daily `site:<wire domain> "<release title>"`, and weekly `site:infinitumwhitepapers.blogspot.com` / `"Dead Reckoning" "Infinitum Corporation"`. Log indexed yes/no. William's action: add both blogspot sites to Search Console and submit their sitemaps (needs his Google login).
